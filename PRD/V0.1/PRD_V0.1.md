## 一、 背景与问题定义

### 1.1 背景现状
在日常办公场景中，现代知识工作者的工作输入高度碎片化。大量需求、通知、待办任务散落在：
- 即时通讯软件（个人微信、企业微信、飞书、钉钉、Slack 等）
- 邮件客户端（Outlook、Foxmail 等）
- 网页与文档（浏览器、协同文档、内部系统等）

### 1.2 核心痛点
1. **录入成本高，打断心流**：遇到一个任务或重要信息，需要复制文本 -> 离开当前工作窗口 -> 打开专门的待办/笔记软件 -> 选择归类 -> 粘贴 -> 设置提醒。复杂的操作导致用户往往选择“等会再记”，最终遗忘。
2. **信息碎片化，上下文丢失**：传统 Todo 工具只记录简短的一句话（如“下周一交报告”），缺乏当时的背景细节（如谁提出的、前置条件是什么、涉及哪些附件/参数），导致后续执行时无法追溯。
3. **传统事项整理耗时**：手工将碎言碎语梳理为项目进展、商务事实、行动项需要大量人工精力，缺乏自动化结构化提炼手段。

### 1.3 产品定位与价值主张
- **定位**：一款**常驻桌面右下角的极简、非阻断式 AI 伴侣**，通过系统级全局划选快捷键，在用户完全不离开当前工作上下文的前提下，自动识别、提炼并归档碎片信息到对应事项，并智能抽取闭环待办。
- **价值主张**：
  - **极致低摩擦录入**：划选 -> 快捷键 -> 松手即完成收集。
  - **AI 智能意图路由**：自动识别归属于哪个事项，自动区分“新事项”与“已有事项增量更新”。
  - **动态事实提炼**：自动提炼长周期事项的“事实摘要”（项目进展、商务财务信息、关键共识）。
  - **无缝待办闭环**：智能识别时间实体，自动生成待办项并按期主动提醒。

## 二、 用户画像与典型使用场景

### 2.1 用户画像
| 维度 | 画像描述 |
| :--- | :--- |
| **典型角色** | 产研经理、项目主管、售前/咨询顾问、独立开发者、重度桌面办公人员 |
| **设备环境** | Windows 10/11 桌面端，常驻企业微信/微信/浏览器/协同办公软件 |
| **使用习惯** | 习惯快捷键操作，极度厌恶打断心流的重型交互，注重数据本地化隐私 |

### 2.2 核心用户场景走查

#### 场景 1：微信/企微沟通中的快速划选收集（高置信度自动归档）
- **动作**：用户在企业微信客户群中看到客户经理发的一段话：“张总，关于A银行项目，我们下周三上午10点前需要提交技术架构白皮书终版，请把性能指标章节补全。”
- **交互**：用户鼠标划选这段文字，按下全局快捷键 `Alt + A`。
- **系统处理**：
  - 后台探测到前台窗口为“企业微信 - A银行项目对接群”；
  - AI 语义分析比对当前进行中的事项，匹配到已有事项【A银行项目交付】；
  - 自动沉淀一条时间轴日志，来源标记为【企业微信 - A银行项目对接群】；
  - 提取事实摘要并增量补充至【A银行项目交付】：“需补全技术架构白皮书终版的性能指标章节”；
  - 提取待办：“提交技术架构白皮书终版”，并智能解析时间为“下周三 10:00”；
  - 屏幕右下角弹出轻量悬浮胶囊 Toast（3秒后自动淡出）：“已记录至【A银行项目交付】，已创建提醒待办：下周三 10:00”。

#### 场景 2：跨应用模糊信息划选（低置信度轻交互确认）
- **动作**：用户在网页上看到一段关于“大模型微调推理成本评估”的数据。划选后按下快捷键。
- **交互**：AI 检索发现有两个相关事项【技术选型调研】与【AI平台私有化部署】，判定两者的匹配度均未达到绝对置信阈值（置信度 < 0.7）。
- **非阻断呈现**：屏幕右下角弹出一个微型小浮窗，呈现选项：
  - 选项1：归属到【技术选型调研】 (快捷键 1)
  - 选项2：归属到【AI平台私有化部署】 (快捷键 2)
  - 选项3：创建新事项：大模型成本调研 (快捷键 3 / 回车确认)
- **闭环**：用户单手按数字键 `1`，浮窗即刻关闭，完成归档，整个过程耗时不到1秒。

#### 场景 3：主界面卡片看板总览与复盘
- **动作**：用户在每日晨会或下班前，呼出主界面。
- **交互**：主界面以卡片式看板呈现进行中的事项，按“最近更新时间”排列。卡片直观显示最近日志、待办未完成数、优先级。
- **下钻**：点击某个事项卡片，展开右侧时间轴抽屉，按时间顺序回溯所有捕获的碎片日志与抽取的事实摘要。

## 三、 功能需求详细规格 (FRD)

按照 **MoSCoW 模型**（Must Have 必须有 / Should Have 应该有 / Could Have 可以有 / Won't Have 本期不做）梳理：

### 3.1 划词捕获与系统级集成 (Must Have)
- **FR-0101 全局快捷键唤醒**：
  - 支持自定义系统级全局热键（默认 `Alt + Shift + A` 或 `Alt + A`）。
  - 支持全局热键冲突自检与友好的改绑提示。
- **FR-0102 选中文本安全读取**：
  - 触发快捷键后，模拟系统复制指令读取所选文本。
  - **剪贴板保护与快照恢复**：在复制操作前备份用户当前剪贴板内容，读取选中文本后异步恢复原有剪贴板，避免破坏用户既有复制历史。
- **FR-0103 上下文元数据捕获**：
  - 捕获选中文本的同时，获取当前聚焦应用进程名（如 `WeChat.exe`、`WXWork.exe`、`chrome.exe`）及窗口标题（如 `A项目攻坚组`），附带当前时间戳作为日志元数据。

### 3.2 AI 智能语义分析与路由引擎 (Must Have)
- **FR-0201 事项聚类与匹配（Intent Matching）**：
  - AI 引擎载入当前所有【进行中】事项的标题、简述、事实摘要。
  - 对比输入文本，输出：匹配的事项 ID、置信度得分（0.0 ~ 1.0）。
- **FR-0202 路由分支判定策略**：
  - **高置信度命中 (Score >= 0.8)**：自动追加至目标事项，不弹打扰弹窗，仅显示轻量成功提示。
  - **明确新事项 (Score < 0.3 且语义为完整独立新主题)**：自动或推荐新建事项，预提取事项标题、类型（工作/生活）、优先级。
  - **模糊歧义 (0.3 <= Score < 0.8 或多事项竞争)**：触发右下角轻量确认窗，列出 Top 2-3 候选事项及“新建事项”选项。
- **FR-0203 事实提炼与事实摘要合并**：
  - 提取输入文本中的关键商务、财务、进度、人员共识等实体事实。
  - 采用增量合并（Incremental Summarization）策略，更新事项层面的事实摘要，避免简单字符串堆叠。
- **FR-0204 待办项智能抽取与时间解析**：
  - 识别文本中的明确行动项（Action Items）；
  - 识别时间实体（绝对时间：2026-09-25 15:00；相对时间：“明天下午3点”、“下周五下班前”、“两小时后”），并换算为标准时间戳（结合当前系统时钟）；
  - 自动绑定到该事项的待办列表中。

### 3.3 事项管理 (Must Have)
- **FR-0301 事项核心属性**：
  - 标题、简要概述、事实摘要、事项类别（工作/生活）、优先级（高/中/低）、重要程度（四象限分类或1-5星）、状态（进行中、挂起、已完成、已归档）、是否置顶。
- **FR-0302 事项生命周期**：
  - 支持手动新增、编辑、删除（软删除）。
  - **状态流转**：进行中 (Active) -> 挂起 (Pending) -> 已完成 (Completed) -> 已归档 (Archived)。
  - **归档与唤醒**：已归档事项不在默认主看板中显示，进入“归档箱”；支持随时将归档事项一键“重新激活 (Re-activate)”。
- **FR-0303 视图与排序**：
  - 默认视图：卡片看板（Card View），展示进行中事项。
  - 排序维度：置顶优先、按最近更新时间降序（默认）、按优先级降序、按创建时间降序。

### 3.4 碎片日志管理 (Must Have)
- **FR-0401 日志时间轴**：
  - 事项详情页以垂直时间轴（Timeline）方式倒序呈现所有历史日志。
  - 每条日志卡片展示：捕获时间、抓取内容原样展示、来源标识（如“企业微信 - 业务一组”）。
- **FR-0402 手动日志录入与编辑**：
  - 支持在事项侧边栏中手动打字快速追加日志。
- **FR-0403 日志转待办与手动提炼**：
  - 针对历史日志，支持点击“一键转待办”或重新发起 AI 事实提炼。

### 3.5 待办管理与主动提醒 (Must Have)
- **FR-0501 待办核心属性**：
  - 待办内容、所属事项 ID、截止/提醒时间、状态（待办、已完成）、是否聚焦/置顶。
- **FR-0502 待办全局看板**：
  - 统一的“今日待办/待办总览”页面，按时间紧急度（已逾期、今天、本周、更晚、无日期）分组。
  - 支持快捷 Check 勾选完成，完成时带有轻量微动效与完成音效提示（可选）。
- **FR-0503 待办聚焦 (Focus Mode)**：
  - 支持将关键待办标记为“聚焦”，置顶在待办列表首位，或固定于桌面极简悬浮条。
- **FR-0504 定时提醒调度与通知**：
  - 本地后台常驻定时调度任务，在提醒时间到达时触发系统原生通知（Windows Toast Notification）。
  - 通知具备可操作性：支持“完成”、“推迟15分钟”、“查看详情”。

### 3.6 系统配置与基础设施 (Must Have)
- **FR-0601 模型服务配置**：
  - 支持自定义 OpenAI 兼容接口（如 DeepSeek、通义千问、Kimi、OpenAI、Claude 或本地 Ollama）。
  - 配置项：API Host, API Key, Model Name, 测速与连通性测试。
- **FR-0602 快捷键管理**：
  - 选中文本快速捕获快捷键、快速打开主面板快捷键。
- **FR-0603 本地数据安全性**：
  - 本地 SQLite 存储，敏感 Key 本地加密存储（DPAPI 或 AES 加密）。

## 四、 业务规则与逻辑边界定义

### 4.1 置信度阈值与路由规则矩阵
| 匹配场景 | 判定条件 | 动作与交互反馈 |
| :--- | :--- | :--- |
| **高置信命中** | 最高匹配得分 $S \ge 0.8$ 且 $S_1 - S_2 \ge 0.2$ | 自动追加到事项 $M_1$，提取事实与待办。桌面右下角淡出式 Toast 提示 3 秒，不抢焦点。 |
| **双重/多重竞争** | 存在两个事项得分接近（$S_1 \ge 0.6$ 且 $S_1 - S_2 < 0.2$） | 右下角轻量小窗提示用户二选一，默认高亮最高分，按数字键或点击确认。 |
| **新事项识别** | 语义分析判断与当前所有事项无强关联，且具备独立事项特征 | 右下角微窗提示：“未匹配到现有事项，推荐新建：【事项标题建议】”，提供回车确认新建或选择已有事项。 |
| **纯噪音/无法理解** | 文本长度过短（如单个标点）或语义无法理解 | Toast 提示“未能识别有效内容，已存入待整理收集箱”或放弃处理。 |

### 4.2 事实摘要增量合并原则 (Incremental Summarization)
- 严禁将每次日志粗暴追加为摘要。
- Prompt 采用“旧摘要 + 新输入日志 -> 增量融合更新后的结构化摘要”，保持摘要字数在 100~300 字之间，分条陈列（例如：【核心目标】、【商务财务条款】、【重要进展】）。

### 4.3 待办相对时间解析基准
- LLM 解析时必须注入当前系统完整基准时间戳（包含星期几），例如：`Current Timestamp: 2026-09-20 23:15:00, Sunday`。
- “明天”自动解析为 `2026-09-21`，“下周一”自动解析为 `2026-09-21`（视自然语言习惯标定）。未指定具体小时时默认设定为 `09:00` 或 `18:00`。
