# 需求概述

## 用户故事：
我的很多工作安排来自于微信，企微等各个信息渠道；我需要将這些碎片信息快速整理到对应的事项中；

## 我设想的实现方式
1. 通过在这些应用中，选中文本，按一个快捷键，将选中的文本快速发送到我的AI助手；
2. AI助手接收到文本后，识别出这个文本归属于哪个事项：
    1. 如果已存在，则提取出这个文本中涉及到的时间，地点，人物，事件等信息，然后判断这些信息是否已经存在于事项列表中；则更新该事项；
    2. 如果不存在，则创建一个新的事项；
    3. 如果无法确认，则在桌面右下角弹出一个小窗口，提示我选择/创建一个事项，然后归档到对应事项上；形成事项日志；
3. AI助手需要为每一个事项，维护一个待办列表和已完成列表；可以对待办列表进行提醒；
4. AI助手需要提供一个主界面，显示所有的事项列表，可以对事项进行归类，分类查看；默认是激活的事件，按照最近更新排序；激活事件可以归档，归档事件存放于归档分类下；归档事件可以进行重新激活；

## 从系统设计的层面看
1. 可以包含几个实体：事项 -> 日志 -> 待办；
2. 事项包含几个属性：标题，概述，事实摘要，优先级，重要程度，状态【进行中，挂起，已完成】；事项类别【生活、工作】；创建时间，更新时间；
3. 日志包括几个属性：创建时间，日志内容（选中的文本）；
4. 待办包括几个属性：内容，时间，状态【待办，已办】；
5. 几个实体的关系是这样的：一个事项包含多个时间日志，一个日志可以抽取出事实摘要补充（如一个项目的重要的商务，财务信息等）；可以抽取成待办（自动识别时间提醒），待办可以设置提醒；

## 从功能角度看：
1. 事项的增删改查；事项置顶/取消置顶功能（点击置顶在列表中）；支持查看事项对应的日志，查看事项对应的待办；
2. 日志手动/快捷键自动增删改查，支持日志AI摘要抽取，日志转待办提醒；
3. 待办的增删改查；待办提醒；待办状态流转【待办/已完成】；待办聚焦/取消聚焦功能（点击置顶在列表中）；


## 从页面结构看：
1. 事项列表页：卡片式呈现，显示事项标题，更新时间，优先级，最新一条日志，最新一条待办；分状态查看，多种排序查看（按优先级，按重要程度，默认按最近更新）；
2. 点击事项可以打开日志侧边栏，按时间轴方式呈现；支持手动/快捷键添加日志，显示日志来源（应用-对话）；支持日志事实抽取，支持转待办；
3. 待办列表页：列表项显示待办内容，所属事项，提醒设置，待办状态check；
4. 配置：配置AI模型API,Key，配置快捷键；

## 交互方式：
1. 尽量采用轻量级，非阻断式的交互方式；
